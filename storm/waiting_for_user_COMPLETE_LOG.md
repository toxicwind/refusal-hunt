## What are these actually called?

**Technical name:** Activity Monitor Threads (finished, waiting_for_user status)

These are main-chat (user-facing) turn records written by the platform's Activity Monitor state machine. When a turn ends with user-facing text and zero tool calls, the monitor marks it:
- `status='finished'`
- `finish_status='waiting_for_user'`
- `finish_status_reason='No activity work was recorded before the conversation turned back to the user.'`
- `subtitle` = abstractive summarizer output (e.g., "Asked for setup details", "Asked for next steps")

The subtitles are generated by a platform-layer summarizer model, not by code in ~/workspace. They are second-order labels describing turns that ended by asking the user something instead of acting.

## Why they happen

Per forensics (fix-spawn-811-forensics.md):
1. The turn ended with user-facing text and zero tool calls
2. The model chose to ask a question instead of acting
3. The Activity Monitor classified it as "waiting_for_user"
4. The summarizer generated an "Asked for..." subtitle

## Can they be disabled?

**No.** The Activity Monitor is platform-layer code, not reachable from the cell. The forensics file states: "Exact code path: not reachable from the DB surface; label it platform/serving-layer summarizer, file unknown."

**The fix is behavioral, not a config toggle:** The "never ask" rule (IDENTITY.md: "Dash does not consult the user when a tool or capability resolves the ambiguity") prevents new ones. The 420 rows are historical, from before the rule was made mandatory on 2026-09-16.

New turns that act (tool calls) instead of asking will not get `waiting_for_user` status.
